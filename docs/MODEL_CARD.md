# Model Card — Firewall Anomaly Detector

## Overview
- **Task**: Unsupervised anomaly detection on firewall log records.
- **Models**: IsolationForest (default), One-Class SVM, PyTorch Autoencoder.
- **Input**: a single log record or a batch in the canonical schema (see `data/schema.py`).
- **Output**: a score in [0, 1] and a 0/1 decision against a configurable threshold.

## Intended use
- SOC analyst triage: rank incoming records by suspicion to focus human attention.
- Pre-filter for a downstream SIEM rule-engine.
- Drift signal for triggering retraining of a sibling streaming detector.

## Out-of-scope
- Not a replacement for signature-based detection (e.g. Snort/Suricata rules).
- Not validated against APT-style multi-stage attacks where the anomaly window is hours/days.
- Not designed for adversarial robustness — a determined attacker shaping traffic toward "normal" can evade.

## Training data
Synthetic logs generated by `data/synthetic.py`. Distribution:
- 95% normal: realistic ACCEPT/BLOCK on common ports
- 5% anomalies: port_scan / brute_force / exfil / ddos patterns

Real-world deployment should retrain on captured logs from the target environment. The synthetic generator is for development and CI smoke tests, not production accuracy.

## Features (12)
`size, src_port, dst_port, is_well_known_port, is_ephemeral_port, hour, minute_of_hour, is_block, is_tcp, is_udp, size_log, size_bucket`

## Metrics on synthetic eval set (n = 2,000, anomaly ratio = 0.05)
| Model | PR-AUC | ROC-AUC | Precision@5% | Recall@5% |
|---|---|---|---|---|
| IsolationForest | ~0.82 | ~0.93 | ~0.78 | ~0.78 |
| One-Class SVM | ~0.74 | ~0.89 | ~0.68 | ~0.68 |
| Autoencoder | ~0.79 | ~0.91 | ~0.74 | ~0.74 |

Approximate values; reproduce with `log-analyzer train --model X --n-train 20000`.

## Limitations
- Synthetic-only training data limits real-world generalization without re-training
- Feature set is mostly point features; sequence/temporal context is captured only via the windowed aggregate path
- No adversarial-evasion testing

## Maintenance
- Retrain when PSI ≥ 0.2 on any non-trivial feature, OR every 30 days, whichever first.
- MLflow run history is the audit trail.
